# Solution — spoilers

All requests below are made in the built-in localhost workbench. Values beginning LAB-ONLY and SESSION are generated by this lab; they have no external use.

## 1. Credential exposure

Send `{}` to `/api/artifact`. Copy the `token` response. The debug endpoint incorrectly exports a service credential without authorization.

## 2. Role escalation

Send to `/api/session`:

```json
{"token":"PASTE_TOKEN_FROM_STEP_1","role":"withdrawal-admin"}
```

Copy the returned `session`. Changing observer to withdrawal-admin works because the vulnerable handler trusts caller-supplied authority.

## 3. Approval bypass

Send to `/api/withdraw`:

```json
{"session":"PASTE_SESSION_FROM_STEP_2","destination":"lab:player","amount":6000000000,"approved":true}
```

The balance reaches zero and the completion panel appears. The requester's own boolean was accepted as independent approval. This is a ledger simulation, not a blockchain transfer.

## Replay and fix

Switch to patched mode. This resets the lab and invalidates previous credentials. The debug endpoint now refuses to export credentials. Even with a credential supplied directly in an isolated test, the service assigns observer on the server and rejects withdrawals. A separate unit test forces an admin identity to verify that the independent approval gate also fails closed.

Compare the explicit `self.patched` branches in `server.py`. Production defenses would require real identity, scoped short-lived credentials, transaction-bound independent approvals, destination and amount policy, signer isolation, monitoring, and revocation. The lab demonstrates these trust-boundary failures in a deliberately simplified form.
